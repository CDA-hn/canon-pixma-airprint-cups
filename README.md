# AirPrint for Canon PIXMA / MegaTank printers with CUPS on Linux

**Print from iPhone and iPad to a Canon PIXMA G3110 / G3010 (and other non‑AirPrint Wi‑Fi printers) using a Debian, Ubuntu or Raspberry Pi server.** No USB cable and no PC left on. Your printer shows up in the iOS Print menu like any AirPrint printer.

🇪🇸 [Leer en español](#español)

---

## The problem

Many cheap Canon ink‑tank printers (PIXMA **G3110**, G3010, G2110, G4110, G3160, G3170, MegaTank series…) are on Wi‑Fi and are Mopria certified. They are **not AirPrint**, so they don't appear on iPhone/iPad.

The usual fix is to share them through CUPS on a Linux box. With these printers that runs into three bugs that are hard to diagnose:

| Symptom | Real cause | Fix in this repo |
|---|---|---|
| iPhone stays on *"Printing…"* / *"Connecting"* forever, and prints only when you SSH in and run `lpstat` | iOS sees CUPS's `_ipps` / `TLS=1.2` advertisement and uses **IPPS (TLS)**. The handshake fails (`Unable to encrypt connection` in `error_log`) and stalls `cupsd`. | Advertise the queue with a **static Avahi service over plain IPP** (no TLS key) and set `BrowseLocalProtocols none` |
| iPhone says *"printed"* but nothing comes out, or the printer sits in `processing` and then shows `job-canceled-at-device` | The stock CUPS `ipp` backend streams the job with **HTTP chunked encoding**, which the Canon firmware handles badly | **`canondirect` backend**: buffers the whole job and sends Create‑Job + Send‑Document with a `Content-Length` |
| Every job waits 25–50 s before starting | cups‑filters asks **colord** over D‑Bus and the call times out on headless servers | Optional `--mask-colord` |
| Printer also advertised on `docker0`, `br-*` and `veth*` addresses | Avahi publishes on every interface | Optional `--iface eth0` |

## Requirements

- A Debian 12/13, Ubuntu 22.04+ or Raspberry Pi OS machine on the **same LAN** as the iPhone. It can be wired.
- The printer on Wi‑Fi with a **fixed IP**. Reserve it by MAC in your router's DHCP settings.
- The printer answering IPP at `ipp://PRINTER_IP/ipp/print`. Canon PIXMA G series printers do.

## Install

```bash
git clone https://github.com/CDA-hn/canon-pixma-airprint-cups.git
cd canon-pixma-airprint-cups
sudo ./install.sh 192.168.1.50 --name "Canon G3110" --iface eth0 --mask-colord
```

Replace `192.168.1.50` with your printer's IP and `eth0` with your server's LAN interface (`ip -br addr`).

On the iPhone: **Share → Print → "Canon G3110"**.

### Options

| Option | Default | Meaning |
|---|---|---|
| `--queue NAME` | `Canon_AirPrint` | CUPS queue name |
| `--name "TEXT"` | `Canon AirPrint` | Name shown on iOS |
| `--location "TEXT"` | `Home` | Location note |
| `--iface IFACE` | all | Advertise only on this interface (recommended if you run Docker) |
| `--mask-colord` | off | Disable colord to remove the 25–50 s delay per job |
| `--stock-ipp` | off | Use CUPS's normal `ipp://` backend instead of `canondirect` |

### Uninstall

```bash
sudo ./uninstall.sh --queue Canon_AirPrint
```

## How it works

```
iPhone ──AirPrint (mDNS + IPP, no TLS)──▶ Linux: Avahi + CUPS ──canondirect (IPP, whole job)──▶ Canon on Wi‑Fi
```

1. **Avahi** advertises `_ipp._tcp` with the `_universal` subtype and a `URF` TXT record. That is what makes iOS list it as AirPrint.
2. **CUPS** receives the job from iOS (PDF / JPEG / URF) and converts it to **PWG raster** with a PPD generated by `driverless`.
3. The **`canondirect` backend** sends the finished raster to the printer in one request and retries while the printer is busy.

See [docs/troubleshooting.md](docs/troubleshooting.md) for the commands used to diagnose each problem.

## Tested with

- Canon PIXMA G3110 (reports as "G3010 series"), Debian 13, CUPS 2.4.10, cups‑filters 1.28, iPhone (current iOS)

Got it working on another model? Please open an issue or PR to add it to this list.

## Español

# AirPrint para impresoras Canon PIXMA / MegaTank con CUPS en Linux

**Imprimí desde iPhone y iPad en una Canon PIXMA G3110 / G3010 (u otra impresora Wi‑Fi sin AirPrint) usando un servidor Debian, Ubuntu o Raspberry Pi.** Sin cable USB y sin dejar una PC encendida. La impresora aparece en el menú Imprimir del iPhone como cualquier impresora AirPrint.

### El problema

Las Canon de tanque de tinta (G3110, G3010, G2110, G4110, G3160…) tienen Wi‑Fi pero **no son AirPrint**. Si las compartís con CUPS te vas a topar con tres fallas:

1. **El iPhone se queda "imprimiendo" para siempre** y solo imprime cuando entrás por SSH y corrés `lpstat`. iOS intenta conectarse por **IPPS (TLS)**, el saludo cifrado falla y `cupsd` se traba. **Arreglo:** anunciar la impresora con un servicio Avahi fijo por **IPP sin cifrado**.
2. **El iPhone dice "impreso" pero no sale nada**, o la Canon queda en `processing` y luego la cancela. El backend `ipp` de CUPS manda el trabajo **por partes (chunked)** y el firmware de la Canon no lo procesa. **Arreglo:** el backend **`canondirect`** arma el trabajo completo y lo manda de un solo golpe.
3. **Cada impresión tarda 25–50 s en arrancar.** cups‑filters espera a **colord**, que no responde en servidores sin pantalla. **Arreglo:** opción `--mask-colord`.

### Instalación

```bash
git clone https://github.com/CDA-hn/canon-pixma-airprint-cups.git
cd canon-pixma-airprint-cups
sudo ./install.sh 192.168.1.50 --name "Canon G3110" --iface eth0 --mask-colord
```

- Poné la IP de tu impresora. Reservala por MAC en el router para que no cambie.
- Poné la interfaz de red del servidor (`ip -br addr`).
- En el iPhone: **Compartir → Imprimir → "Canon G3110"**.

### Consejos

- La Canon solo usa **2.4 GHz**. Si tenés malla (mesh) y la impresora se pega a un nodo lejano con señal débil, reiniciá ese nodo desde el router.
- Si imprime todo en blanco o muy tenue, el problema es la tinta o el cabezal, no el servidor. Hacé una limpieza de cabezal.
